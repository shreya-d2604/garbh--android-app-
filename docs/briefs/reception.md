# Brief: reception agent

Branch `agent/reception`. Read AGENTS.md, docs/contracts.md, docs/ui-kit.md, docs/local-dev.md first.

## Goal
The front desk works end to end: register walk-ins, verify app registrations, run the
appointment book, check patients in, and handle visits due / doctor unavailable. You also own
the **booking engine** (SQL) that patients, doctors and admins depend on, so build and test it
first and make it rock solid.

## You own
- `app/reception/**`, `src/features/reception/**`, `src/i18n/en/reception.json`
- Migrations `20261024000000`-`20261024999999`, tests `supabase/tests/reception_*.test.sql`,
  optional `supabase/seeds/reception.sql`

## SQL to build (contracts in docs/contracts.md §2; keep stub signatures identical)
1. `available_slots`, `book_appointment`, `reschedule_appointment`, `cancel_appointment`,
   `set_appointment_status` (replace stubs). Read rules from `hospital_settings`. Wall-clock
   availability is in `hospital_settings.timezone` (Asia/Kolkata). Catch `23P01` and raise `SLOT_TAKEN`.
   Lock the doctor's day (`pg_advisory_xact_lock(hashtext(doctor_id::text))` or similar) before checks.
2. `verify_patient`, `merge_patients` (replace stubs).
3. New: `register_patient(p_details jsonb) returns uuid` (desk walk-in: patient verified with
   MRN, active pregnancy `lmp_source='clinician'`, primary doctor in `care_team`, visit plan is
   generated by the existing trigger) and `mark_visit_contacted(p_visit uuid, p_note text)`.
4. Policy: `patients_reception_update` (receptionist may edit demographics; not `user_id`,
   `verified_*`, `deleted_at` - enforce with a trigger in `private` or do edits via RPC).
   Appointments get NO direct write policies: all writes through RPCs.
5. Revoke/grant execute on every new function (AGENTS.md §4).

## Screens (PLAN.md §7.5)
- Tabs: Today's desk (home), Calendar, Register, Verify queue, Visits due (+ Doctor unavailable).
- **Register patient**: demographics, MRN (manual or auto-suggest), email (= app invite: the
  patient signs in with this email and is auto-linked, docs/contracts.md §1), LMP, primary doctor
  (from `doctor_directory`/profiles), consent recorded. Duplicate check on phone / name + DOB
  before saving (query `patients`).
- **Verify queue**: unverified `registration_source='app'` patients, today's arrivals first
  (join today's appointments). Assign MRN, correct details, optional merge into an existing desk
  record.
- **Appointment book**: day/week per doctor, free slots from `available_slots`, appointments live
  via `useRealtimeInvalidate({ table: 'appointments', ... })`, `StatusChip` "App" for
  `booking_channel='app'`. Book / reschedule / cancel; only care-team doctors selectable; link to a
  planned visit.
- **Today's desk**: check in, mark no-show (`set_appointment_status`).
- **Visits due**: planned visits with `due_from` within 14 days and no appointment, plus overdue;
  one-tap booking; "Called patient" note (`mark_visit_contacted`).
- **Doctor unavailable**: active appointments overlapping `doctor_time_off`, rebook with a backup.
- Receptionists never see clinical data (RLS already hides it; don't try to query it).

## Tests (acceptance)
pgTAP for every rule in PLAN §13 "booking RPCs": outside availability, during time off, inside lead
time, beyond advance window, after cancel cutoff, non-care-team doctor, over max upcoming,
unverified limit = 1, another patient's appointment, first-visit primary assignment, doctor not
accepting, staff bypass of cutoff/lead, `available_slots` correctness (time off and booked slots
excluded, timezone), status transitions per role, verify (MRN uniqueness), merge. Concurrency:
a `reception_concurrency` test or `scripts/`-free shell snippet in your test notes proving two
bookings of one slot -> exactly one succeeds (the exclusion constraint is the final guard).
Jest: calendar/slot grouping helpers, duplicate-check logic, form schemas.

## Do NOT
Touch patient/doctor/admin screens, `src/components`, shared files, or other agents' migrations.
Do not add notification inserts: the backend agent's triggers on `appointments` / `patients`
produce them.
